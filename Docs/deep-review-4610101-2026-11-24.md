## R30 GraphQL JSON 内联凭证穿过默认 MCP 脱敏

定位：[ExportRedaction.swift:113](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorCore/Export/ExportRedaction.swift:113)。

脱敏器把任意 JSON 字段 `query` 都当成 URL 查询参数，直接送进 `sanitizeQuery`。标准 GraphQL JSON 的 `query` 实际是操作文档；内联 `password` 字符串不含 URL 的 `=` 结构时，会原样返回，绕过普通文本的敏感字段处理。

完整入口为 MCP tools/call → LocalControl 的 MCP 模式 → AutomationControl → `redactedCopy` → SessionRecord/body 脱敏。`get_flow`、`export_flows` 及 `copy_as_code` 都会受影响；代码导出还会直接使用这份已被认为安全的副本。

**实际验证：**直接编译当前生产 ExportRedaction，合成 GraphQL 内联密码在 JSON、原生 SessionRecord 的 base64 正文及 SSE JSON 中仍保留。相同内容作为普通 GraphQL 文本会被脱敏。既有 44 项 MCP 隐私检查全部通过，说明缺少此类文档夹具。

建议按真实结构区分 URL query 元数据与 GraphQL 操作文档，对非 URL 参数文本继续做敏感值处理；覆盖上述三种容器和代码导出。证据：`/tmp/proxymirror4610101-security-review/graphql-privacy.log`。

## R31 HTTP/2 早期响应后遗留上游半流

定位：[HTTP2ProxyStream.swift:143](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorCore/Proxy/HTTP2ProxyStream.swift:143)、[channelInactive:902](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorCore/Proxy/HTTP2ProxyStream.swift:902)。

上游在 POST 请求体结束前返回完整响应，例如 401/413，`finishResponse` 会把 `responseEnded` 和 `completedNormally` 置为 true。随后下游请求结束时，处理器设置 `requestEnded=true`，却因为 `responseEnded` 而不再转发请求 `.end`。下游流关闭时，两个状态又让关闭上游的条件为 false。

这使上游 H2 child 仍处于请求半边未关闭的状态。[HTTP2UpstreamPool.swift:240](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorCore/Proxy/HTTP2UpstreamPool.swift:240) 仅在 child.closeFuture 完成时释放 activeStreams；连续早期响应可累积悬挂流，并影响同一连接上的后续请求及空闲回收。

**实际依赖验证：**使用锁定的 NIO 2.86.2/HTTP2 1.38.0 和本机 TCP 源站，未结束 POST 收到 413+END_STREAM 后：

```text
EARLY_RESPONSE_RECEIVED=true CLIENT_CLOSED=false SERVER_CLOSED=false
AFTER_REQUEST_END CLIENT_CLOSED=true
```

这证明库不会自动补上请求半边。产品的遗漏由上述状态机源码确认；本轮没有运行完整 macOS 代理。建议在早期响应终止时明确结束或取消上游请求半边，补早期拒绝上传、连接复用及 activeStreams 回收回归。证据：`/tmp/pm-review-h2-early/root-result.log`。

## R33 Compose trailers 被当成正文

定位：[HTTPRequestTransport.swift:98](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorFoundation/HTTP/HTTPRequestTransport.swift:98)、[正文累计:177](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorFoundation/HTTP/HTTPRequestTransport.swift:177)。

## R35 实时更新令后台排序持续无法完成

定位：[TrafficStore.swift:98](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorCore/Model/TrafficStore.swift:98)、[refreshLiveRows:364](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorCore/Model/TrafficStore.swift:364)。

## R41 注入运行时在跨功能适配层被共享实例替代

定位：[AutomationControl.swift:144](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorCore/DesktopApplication/AutomationControl.swift:144)、[ComposeService.swift:259](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorCore/Export/ComposeService.swift:259)。

## R42 CA 安装没有绑定提权输入的路径和内容

定位：[SystemProxy.swift:352](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorCore/System/SystemProxy.swift:352)。

CA 先写入用户临时目录中的固定文件，再把路径放入 shell 双引号，交给管理员授权后的 AppleScript 执行。双引号不能防止 shell 命令替换；若该实例的可写 TMPDIR 路径被环境控制而含 shell 元字符，正常安装授权会在提权 shell 中解释这些字符。

另外，授权等待期间同 UID 程序或另一次 revealCAFile 可替换固定文件；提权命令只重新按路径读取，没有绑定所选 CA 的指纹。存在安装对象与用户所选 CA 不一致的窗口。

**边界与验证：**路径构造式已用 Swift Foundation 和只打印 argv 的无特权替身验证；没有执行 security、osascript 或提权。命令解释需要控制该实例 TMPDIR 且用户批准安装，默认系统路径没有所测字符；文件替换需要同 UID 写权限。这不是无交互远程问题。

建议使用按参数调用的受控提权接口，校验所选 DER 指纹并使用不可变受控副本；若保留 shell，必须正确进行 POSIX 路径引用。证据：`/tmp/proxymirror4610101-security-review/ca-path-boundary.log`。

## R43 固定 Linux CI 无法编译进程执行器

定位：[PreviewProcessRunner.swift:102](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorFoundation/Process/PreviewProcessRunner.swift:102)、[DeviceCommandRunner.swift:132](/home/say/work/github/ProxyMirror/Sources/ProxyMirrorFoundation/System/DeviceCommandRunner.swift:132)。

CI 固定 swift:6.0.3-jammy，glibc 2.35 的头文件把 addclosefrom_np 声明放在 GNU 特性宏下；Swift 导入 Glibc 时看不到它。两处直接调用都触发编译错误，Linux lane 因而无法运行任何 Foundation 测试。

**实际证据：**CI 编译日志明确报告 cannot-find；同机最小 harness 原样导入 glibc 2.35 头会复现，仅加入 GNU 声明宏后 typecheck 通过。本机旧验证采用 Ubuntu 24.04/glibc 2.39，声明可见，所以 41 项通过。不是测试计时差异。

建议用显式 C shim/兼容包装控制声明和平台边界，并在固定镜像编译验证。需保留关闭非标准 FD 的语义，避免恢复此前的继承竞争。证据：[Foundation job](https://github.com/SebastianLavertheDe/open-proxyman/actions/runs/45347631458/job/138285943905)、`/tmp/pm-review-4610101-foundation-job.log`。

## R44 原生测试自身的数据竞争阻断 TSan

定位：[DiagnosticHeaderChecks.swift:95](/home/say/work/github/ProxyMirror/Tests/ProxyMirrorCoreChecks/DiagnosticHeaderChecks.swift:95)、[AsyncBox.swift:15](/home/say/work/github/ProxyMirror/Tests/ProxyMirrorCoreChecks/AsyncBox.swift:15)。

Map Local 原生测试把 EmbeddedEventLoop 传给后台 NIOThreadPool；worker 完成 promise 时，主线程还在该非线程安全 loop 注册/运行回调。CI 实际输出 EmbeddedEventLoop is not thread-safe，并由 TSan 报告 EventLoopFuture._setValue 竞争后以 134 中止。

独立的 NSBox 也在 worker 持锁写 done，却在 wait 中无锁读 done；CharlesImportChecks 存在真实跨线程调用。后者为源码确认，本机 Linux TSan 初始化失败，未声称已运行复现第二个竞争。

建议异步生产路径使用真实事件循环，测试信箱统一同步/条件等待。该结果不能被归因为生产 NIO EventLoop 的竞争，也不能当作 R16 产品线程问题已经通过验证。证据：[TSan job](https://github.com/SebastianLavertheDe/open-proxyman/actions/runs/45347631458/job/138285943386)、`/tmp/pm-deep-review-ci/tsan-api.log`。

## R45 原生断言没有跟随当前合同更新

定位：[test_cli.py:236](/home/say/work/github/ProxyMirror/Scripts/test_cli.py:236)、[ComposePersistenceChecks.swift:60](/home/say/work/github/ProxyMirror/Tests/ProxyMirrorCoreChecks/ComposePersistenceChecks.swift:60)。

至少三类确定的陈旧断言使原生检查无法通过：

1. CLI 取消仍要求 `_error` 含中文“客户端”，但当前稳定诊断为 `The client connection closed`。CI 中 failed 状态和部分正文捕获检查已通过，仅文案断言失败；应检查 `_proxyMirrorFailure.code == network_client_closed`。
2. “未知 Session 版本”夹具使用 version=2，而 currentVersion 已为 2。产品正常接受合法文件，测试却要求抛错；应取 currentVersion+1 并单独验证当前版本成功。
3. 地区数字断言硬编码 `1000 Matches` 等无分组形式，而实际区域格式为 `1,000 Matches`。应固定测试 Locale 并按格式合同断言，不应把合法分组当产品错误。

上述失败分别由 release/TSan 日志或当前模型代码确认。Darwin 对前导零 IPv4 的处理还与一个跨平台夹具假设不同，但 ACL 最终按同一解析器的数值字节比较，本轮未确认鉴权或自连接绕过。

建议修正测试合同并重跑 native lanes；debug 超时仍需增加逐 case 进度和边界超时定位，当前不猜测具体产品根因。证据：[release job](https://github.com/SebastianLavertheDe/open-proxyman/actions/runs/45347631458/job/138285943715)。
